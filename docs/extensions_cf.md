# B1/B2：协同模型收敛与任务方向协议

本实现仅写入 `results_extensions/v1/stage_b/`。原始 `collaborative.py`、六轮训练器、`results/` 和 `reports/` 不变。所有 2015–2017 结果仍为探索性开发分析。

`configs/extensions_v1.json` 是全局协议。运行器在第一次历史评价前，向各模型族的 `protocol.json` 写入全局协议哈希、完整网格、源码/依赖哈希、数据字节哈希、线程数与规则。已有族协议身份不一致时拒绝混用；应切换新版本输出目录。每条轨迹重新计算身份，核验所有持久文件；轨迹状态过期或损坏时隔离到 `.stale_时间戳` 并重新确定性训练。旧的失败记录保留。

## 模型与预算

原 `mf_bpr`、`lightgcn`、`simplex` 的模型、传播图、历史、原生损失、正例顺序、负商品采样和 12 配置网格直接复用。新增 `lightgcn_user` 采用同一 LightGCN 网格与图，固定商品比较正用户、负用户的 BPR 损失；ego L2 与原版本的逐样本缩放一致。负用户从该前缀全部合格用户中均匀有放回抽取，并排除该商品的所有历史评分，包括低评分和拟合窗口以前的评分，不读未来正例。每轮每个唯一拟合正边恰好使用一次；BPR 每边一个配对，SimpleX 每边十个负例配对。

在 `cds_2015_d30` 上，每族运行原网格全部 12 配置 × 三种子 101/202/303。单条连续轨迹先运行 50 轮，每轮记录历史 Tail80 I-NDCG@20；只允许第 6、20、50 轮参与三种子均值选择。并列先选更少轮，再选较早的网格下标。只有当该族赢家为第 50 轮且优于同配置第 20 轮至少 1% 时，将该族全部 36 条轨迹连续延长至 100 轮，并允许第 100 轮参与选择。当第 20 轮均值绝对值严格小于 `1e-8` 时，以绝对差 `1e-4` 代替相对阈值。选择要求完整矩阵，失败或缺失不能生成选定配置。

四个族共 144 条历史轨迹、60 条最终轨迹。最终每族选定一次配置与轮数，在 2015/2016/2017 三起点、11/22/33/44/55 五种子上训练；训练不评价最终查询。保存模型和固定选择记录后才打开查询，最终保留 All/Tail50/Tail80 的 @10/20/50 排序指标与候选、目录及可评价掩码。最终查询不参与轮数和配置选择。

## 持久化与运行度量

`hpo/trial_XX/seed_N/` 包含 `history.json`、`complete.json`、`frozen.json`，以及 `checkpoint_006.npz`、`checkpoint_020.npz`、`checkpoint_050.npz` 和条件性 `checkpoint_100.npz`。`last_state.npz` 是每轮原子替换的未压缩最新状态，包含模型、完整 Adam 一/二阶矩与步数、训练采样 RNG、Python/NumPy/Torch RNG、历史与检查点哈希。没有重新初始化优化器的伪续训。仅里程碑模型压缩，降低逐轮压缩时间与磁盘峰值。

每轮记录样本加权损失、全部可训练参数梯度的 L2 范数、实际 Adam 参数差的 L2 范数、平均/最大梯度、平均/累计更新范数、正边数、配对数、更新次数及各项累计值、训练和历史评价秒数、进程 RSS 高水位。运行时字段包含保存以外的分项时间，`runtime.json` 的 invocation_seconds 包含保存与哈希时间；恢复后的该字段仅代表本次进程调用。RSS 是进程高水位，多个顺序任务可能继承先前峰值，不解释为独立任务的内存差异。

各族 `selected.json` 保存全部候选的三种子均值、平局顺序、扩展判定与每条历史完成记录哈希。最终复用时重新验证精确的 12×3 单元集合、各单元身份及 50/100 轮预算，并从历史指标重新计算扩展条件、全部候选和赢家。`final/cds_YYYY_d0/seed_N/` 保存 `model.npz`、`test.npz`、`result.json`、`complete.json` 与继续训练状态。完成记录要求完整的角色专属文件清单，并校验全部关联文件，不以文件存在判断成功。状态收据同时校验外部历史和冻结身份；损坏历史不会因最新训练状态已经达到预算而重新变为可信。全局与族协议、配置、代码、数据、依赖都进入逐运行身份；直接调用训练函数也绑定用户、商品 ID 和拟合/过去历史指纹。

## 入口

```bash
.venv/bin/python scripts/run_extension_cf.py --list-tasks
.venv/bin/python scripts/run_extension_cf.py --pilot
.venv/bin/python scripts/run_extension_cf.py --hpo-only
.venv/bin/python scripts/run_extension_cf.py --final-only
.venv/bin/python scripts/run_extension_cf.py --retry-failed
```

`--methods lightgcn lightgcn_user` 限定本次调度的模型族，不削减任何族内网格；`--protocol` 默认读取上述全局 JSON，`--results-dir`（或 `--output-root`）改变独立输出根。`--pilot` 在各族第一个网格、种子101上运行两轮历史前缀计时，写在独立 `pilot/` 目录，不计入正式矩阵，也不使用最终查询。可用 `--pilot-epochs` 增加计时轮数。`--retry-failed` 保留失败证据后允许重试已有失败单元，同时恢复/运行其它缺失单元。单工作进程固定一个 Torch、BLAS 和 OpenMP 线程；同机最多三个训练进程，由总调度控制。

小型合成测试验证历史排除与未来不变性、固定商品损失公式、原六轮模型逐参数一致、连续与恢复训练逐参数一致、状态损坏隔离重算、完整三种子选择与扩展边界、最终评价前冻结记录、完成标记内容校验。真实数据计时仅依据实际 pilot 记录，不能预先宣称充分完成。
